## Finding 7 - bazel test targets (code reading, not run)

* Python tests use `torch_tpu_py_test` (`build_files/build_defs.bzl:991`).
  One `.py` per target. Targets without a `requires-tpu-*` tag are CPU
  tests (for example `//tests:env_utils_test`).
* `--//:test_wheel=True` (alias `--test_wheel=True`) swaps the source deps
  for `//:torch_tpu_py_import`. Without `--define PYTHON_VERSION=...` that
  uses `//ci/wheel:torch_tpu_wheel`, the target the base build makes.
* Candidate commands (run from the base worktree after the build is done,
  one bazel at a time):

```bash
# A. Against the built wheel. Same flags as the base build, so most actions
#    should be cache hits.
bazel test --config=wheel_common --config=no_rbe \
  --spawn_strategy=sandboxed,local --strategy=sandboxed,local \
  --//:test_wheel=True --test_output=errors \
  //tests:env_utils_test

# B. From source (CI style). Different config from the wheel build, so
#    expect a large extra build. Use only if A does not work.
bazel test --config=no_rbe \
  --spawn_strategy=sandboxed,local --strategy=sandboxed,local \
  --test_output=errors //tests:env_utils_test

# C. TPU test: build without the lock, then run with the lock.
bazel build --config=wheel_common --config=no_rbe \
  --spawn_strategy=sandboxed,local --strategy=sandboxed,local \
  --//:test_wheel=True //tests:empty_test
flock /root/tpu.lock timeout 3600 bazel test --config=wheel_common \
  --config=no_rbe --spawn_strategy=sandboxed,local \
  --strategy=sandboxed,local --//:test_wheel=True \
  --local_test_jobs=1 --test_output=streamed //tests:empty_test
```

* Do not use `--config=testone` after the workaround flags. It re-applies
  `--config=local`, which sets `--spawn_strategy=standalone` again.
* Hypothesis: A reuses the wheel. Not verified, because the flag change can
  cause a new analysis and maybe some rebuild.

## Recommended recipe for workers

Python-only fix (no bazel, works now):

```bash
E=/root/torch_tpu/.claude/tmp/<task>
I=/usr/local/lib/python3.13/dist-packages/torch_tpu
# 1. Overlay: real copies of non-.so files, symlinks to .so files.
mkdir -p $E/ov && cd $I
find . -type d -exec mkdir -p $E/ov/torch_tpu/{} \;
find . -type f ! -name '*.so*' -exec cp -p {} $E/ov/torch_tpu/{} \;
find . -type f -name '*.so*' -exec ln -s $I/{} $E/ov/torch_tpu/{} \;
# 2. Copy the changed files from the fix branch into $E/ov/torch_tpu/.
#    Never write to a symlink (it points at the installed file).
#    For a fix based on upstream/main, copy ALL upstream .py files first
#    (see .claude/tmp/E6/overlay_main), then the changed files.
# 3. Repo-tree copy for tests:
git -C /root/torch_tpu archive <branch> tests perflab | tar -x -C $E/repo
# 4. Run (CPU test):
cd $E/repo && PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=$E/ov \
  timeout 600 python3 -m tests.<name> <args from tests/BUILD>
# 5. TPU test: same, wrapped in the lock.
PYTHONPATH=$E/ov timeout 1200 flock /root/tpu.lock timeout 900 \
  python3 -m tests.<name> ...
# Check torch_tpu.__file__ points into $E/ov. Do not use python3 -I
# (it drops PYTHONPATH).
```

C++ fix (after the base build is done):

* Make a worktree from the base commit. Build with the base flags plus the
  #6508 workaround. Share the disk cache (`/root/.bazelrc`).
  Only one bazel command on the machine at a time.
* Install the wheel into a venv
  (`uv venv`, `pip install bazel-bin/ci/wheel/*.whl
  --extra-index-url https://download.pytorch.org/whl/cpu`), then run the
  test as above with the venv python. Or try command A/C.

Before a PR: `BASE_SHA=upstream/main nox -s lint` on the committed branch.
