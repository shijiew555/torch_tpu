# S3-E2 - Vision and diffusion models (TPU)

Result: 3 confirmed bugs, 1 feature gap.
Eager training of most torchvision classification, segmentation and
video models, and of diffusers UNet, VAE, DiT and SD3, matches CPU.
The best finding: some TPU kernels drop channels_last strides.
This breaks `view()` in eager code and in the compiled backward of the
diffusers VAE.
The second finding: indexing an empty tensor aborts the process.

Setup: discovery venv (torch 2.16.0.dev20261112, torch_tpu `afd6943a`).
I installed `torchvision==0.30.0.dev20261122+cpu` (nightly CPU index,
`--no-deps`) and `diffusers==0.43.0` with `uv pip install`.
Both installs worked. torch and torch_tpu did not change.
All TPU runs used `torch.set_float32_matmul_precision("highest")`.
Scripts and logs: `$COORD/scratch/S3-E2/`.

## F1. Some TPU kernels drop channels_last strides (eager and compile)

Status: confirmed.

Several TPU kernels return a contiguous (NCHW) output for a channels_last
input.
CPU and the meta kernels return a channels_last output.
Thus code that uses `view()` on the result works on CPU and fails on TPU.
In `torch.compile`, fake tensors use the meta strides, so the graph has a
`view` that is valid for meta strides but not for the real TPU strides.

Repro 1 (eager and compile): `scratch/S3-E2/cl_view.py`

```python
def f(x):
  return torch.relu(x).permute(0, 2, 3, 1).view(2, -1)
x = torch.randn(2, 8, 4, 4).contiguous(memory_format=torch.channels_last).to(dev)
```

Command: `python cl_view.py <cpu|tpu> <eager|compile>`

```
input strides (128, 1, 32, 8) relu strides (128, 1, 32, 8)    # cpu
OK cpu eager (2, 128)
input strides (128, 1, 32, 8) relu strides (128, 16, 4, 1)    # tpu
FAIL tpu eager RuntimeError view(): cannot create a view of shape [2, 128] from the input tensor of shape [2, 4, 4, 8] and strides [128, 4, 1, 16] ...
OK cpu compile (2, 128)
FAIL tpu compile BackendCompilerFailed backend='tpu' raised: ...
```

Repro 2 (real model): `scratch/S3-E2/vae_compile.py`.
A tiny diffusers `AutoencoderKL` (from config) fails in the compiled
backward on TPU.
The VAE attention block output is channels_last (transpose + reshape).
The next GroupNorm backward on TPU returns contiguous `grad_input`.
Then the AOT backward graph runs `aten.view(transpose_8, [512, 64])`.

```
FAIL tpu tpu enc       RuntimeError view(): cannot create a view of shape [512, 64] from the input tensor of shape [2, 256, 64] and strides [16384, 1, 256] ...
FAIL tpu aot_eager full  (same error)
OK   cpu aot_eager full
OK   tpu tpu dec / tpu tpu mid (decoder and mid block alone work)
```

Expected: same as CPU (strides kept, no error).

Sweep of output strides for a channels_last input, TPU vs meta
(`cl_strides.py`, `cl_unary.py`).
Not kept on TPU: `relu`, `abs`, `gelu`, `hardswish`, `relu6`, `sqrt`,
`silu_backward`, `hardswish_backward`, `convolution_backward[0]`
(grad_input), `native_batch_norm`, `native_batch_norm_backward[0]`,
`native_group_norm_backward[0]`, `native_dropout`,
`_adaptive_avg_pool2d_backward`.
Kept on TPU: `exp`, `sigmoid`, `tanh`, `neg`, `silu`, `leaky_relu`,
`elu`, `softplus`, mul, add, clone, `.to(bf16)`, `gelu_backward`,
`threshold_backward`, `sigmoid_backward`, `native_group_norm`, max/avg
pool forward and backward, `upsample_bilinear2d` and its backward,
`upsample_nearest2d`.
Pattern (hypothesis): ops that are registered as `.out` (structured)
kernels keep strides, because PyTorch allocates the output.
Functional `TT_KERNEL`s that make the output with `DispatchOp` /
`MakeTensor` (for example the `UnaryOp` helper) always make it contiguous.

Root cause (by source reading, same on upstream/main):
* `csrc/ops/unary_aten_kernels.cc`: `AtenRelu` -> `UnaryOp` (line 106/135).
* `csrc/ops/group_norm/group_norm_aten_kernels.cc`:
  `AtenNativeGroupNormBackward` returns `MakeTensor(d_input_buf)`
  without the input memory format.
* Precedent: `csrc/ops/rms_norm/rms_norm_aten_kernels.cc:181` checks
  `input.suggest_memory_format()` for ChannelsLast.
* No commit in `afd6943a..upstream/main` touches these kernels.

Fix: C++.
Option A (small, ~5 lines per kernel + tests): return
`result.contiguous(input.suggest_memory_format())` for channels_last
input in `UnaryOp` and in the norm/conv backward kernels.
Option B (central): make `DispatchOp`/`MakeTensor` take the memory format
from the input. Larger, needs a maintainer decision.
A first PR could fix `UnaryOp` plus `native_group_norm_backward` (the VAE
blocker) with a test that compares output strides with the meta kernel.

Test: for each op, compare `op(x_cl.to("tpu")).stride()` with
`op(x_cl.to("meta")).stride()`; plus the compiled VAE encoder backward.

Overlap: no issue or PR for channels_last strides
(`gh issue/pr list --search channels_last`, "memory_format",
"stride mismatch meta").
Similar class, closed: #5949 (splash_sdpa fake strides, "view(): cannot
create a view").

Impact: high. Diffusers VAE training with `torch.compile` fails, and any
channels_last model code that uses `view` fails in eager.
channels_last is common in vision code.

## F2. Indexing an empty tensor with an empty index aborts the process

Status: confirmed.
Found in a RetinaNet training step (the loss code indexes an empty
tensor when no anchor matches).

Repro: `scratch/S3-E2/empty_index.py`, run with `run_empty.sh`.

```python
x = torch.empty(0, device="tpu")             # also int64, or (0, 4)
i = torch.empty(0, dtype=torch.long, device="tpu")
print(x[i].cpu())                             # also torch.index_select(x, 0, i)
```

Actual (each case):

```
tensor([])
loc("index/index"): error: slice size (1) is out of bounds for operand dimension (0) at index 0
LLVM ERROR: Failed to infer result type(s):
"stablehlo.gather"(...) {} : (tensor<0xf32>, tensor<0x1xi64>) -> ( ??? )
*** SIGABRT received ...
  mlir::stablehlo::GatherOp::build()
  torch_tpu::(anonymous namespace)::BuildIndexShlo()
  torch_tpu::Traversal::BuildMlirModule()
```

The print shows the right empty result first.
Then the background compile of the lazy graph aborts the process.
`index_select` aborts the same way (`loc("index_select/index_select")`).
Expected: empty tensor, no abort (CPU).
Works: non-empty `x` with an empty index; bool mask then index.

Root cause: `csrc/ops/index/index_aten_kernels.cc`, `BuildIndexShlo`
(line 81).
It sets `gather_slice_sizes` to 1 for each indexed dim (line 150).
When the operand dim size is 0, slice size 1 is out of bounds, and
`stablehlo::Gather` fails type inference with an LLVM fatal error.
Same code on upstream/main (only a BUILD change since `afd6943a`).

Fix: C++, about 10-20 lines plus tests.
If an indexed operand dim is 0 (then the index must be empty), skip the
gather and return an empty result of the output shape.
Check the same for `index_select` (line 281 calls `BuildIndexShlo`), and
maybe `gather`/`take`/`embedding`.

Overlap: none found ("empty index gather", "slice size out of bounds",
"empty index_select").

Impact: high. A process abort, not an exception.
It hits detection losses (RetinaNet), and any code that indexes a
filtered empty tensor.

## F3. torchvision detection ops are not implemented on TPU

Status: confirmed. Feature gap, clear error.

`ops.py`: `torchvision::nms`, `batched_nms`, `roi_align`, `roi_pool`,
`ps_roi_align`, `deform_conv2d` raise
`RuntimeError: operator 'torchvision::nms' is not implemented for TPU.
Please file a feature request`.
So Faster R-CNN, Mask R-CNN, RetinaNet inference and training cannot run.
No CPU fallback. The error is clear.
`box_iou`, `generalized_box_iou`, `box_convert`, `clip_boxes_to_image`,
`remove_small_boxes`, `sigmoid_focal_loss`, `stochastic_depth` match CPU.
Fix: register Python or C++ lowerings for the `torchvision::` ops
(`roi_align` can be gather-based; `nms` needs a fixed-size loop).
Medium to large. No issue found (`gh issue list --search torchvision`,
`nms`).
Impact: medium. Detection users are blocked, but this is a feature, not a
bug.

## F4. Missing aten ops that vision models hit (all in UNREGISTERED_OPS on main)

Status: confirmed (clear "not implemented" errors).
`upsample_trilinear3d` (3D UNet, video), `adaptive_max_pool2d` backward,
`adaptive_max_pool3d`, `max_unpool2d`, `fractional_max_pool2d`,
`kthvalue`, `median.dim_values`.
None of the 20 tested torchvision and diffusers models needed them.
`mish` is also missing, but it has issue #5679 and open PR 5960 (dead end).

## Dead ends (one line each)

* BN `running_mean` differs after a train step: fixed on main by
  392146d00 (#5667).
* DiT out rel 0.14 in train mode: `LabelEmbedding` drops class labels at
  random; in eval mode it matches.
* tv2 `Resize` uint8 "mismatch 215": my test counted differing elements;
  real max diff is 1 (rounding).
* uint8 bicubic interpolate (no antialias) max diff 18 in 39/1440 pixels
  vs CPU: CPU uses a special uint8 path; low use; not checked further.
* uint8 antialias interpolate raises `NotImplementedError` on TPU; CPU
  has a uint8 kernel, but torchvision casts to float on non-CPU, so users
  do not hit it.
* inception_v3 at 96 px and vit_b_16 at 32 px: input too small for the
  model (CPU fails the same way).
* `mish` missing: issue #5679, open PR 5960.
