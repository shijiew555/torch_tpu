## Finding 1 - `Tensor.unfold` backward and `F.fold` (col2im) give bf16-level errors for float32 (confirmed)

* Impact: high. `F.fold` is also the backward of `F.unfold` (im2col).
  `Tensor.unfold` is used for sliding windows, patch extraction, and
  conv-like layers. Gradients lose about 3 decimal digits.
  `torch.set_float32_matmul_precision("highest")` does not help.
* Repro: `repro_unfold_grad.py`, `repro_fold.py`.

```python
# repro_unfold_grad.py
import torch
torch.set_float32_matmul_precision("highest")
torch.manual_seed(0)
x = torch.randn(5, 5, 5, 5)
g = torch.randn(3, 5, 5, 5, 3)  # x.unfold(0, 3, 1) has shape (3, 5, 5, 5, 3)
def grad(x, g):
  x = x.detach().requires_grad_()
  x.unfold(0, 3, 1).backward(g)
  return x.grad
ref = grad(x.double(), g.double())
c = grad(x, g)
t = grad(x.to("tpu"), g.to("tpu")).cpu()
print("cpu f32 max err:", (c.double() - ref).abs().max().item())
print("tpu f32 max err:", (t.double() - ref).abs().max().item())
print("tpu f32 bf16-rounded-input err:", (grad(x, g.bfloat16().float()).double() - ref).abs().max().item())
```

```python
# repro_fold.py
import torch
import torch.nn.functional as F
torch.set_float32_matmul_precision("highest")
torch.manual_seed(0)
cols = torch.randn(2, 3 * 3 * 3, 36)
ref = F.fold(cols.double(), (8, 8), 3)
t = F.fold(cols.to("tpu"), (8, 8), 3).cpu()
print("F.fold (col2im) tpu f32 max err:", (t.double() - ref).abs().max().item())
print("F.fold cpu f32 max err:", (F.fold(cols, (8, 8), 3).double() - ref).abs().max().item())
```

* Command: `cd .claude/tmp/E3; flock /root/tpu.lock timeout 90 python repro_unfold_grad.py`
  (same for `repro_fold.py`).
* Actual:
  * unfold backward: `cpu f32 max err: 1.79e-07`, `tpu f32 max err: 0.01026`.
    The TPU error is exactly the error of a CPU grad with the cotangent
    rounded to bf16 (also 0.01026). So the TPU rounds the input to bf16.
  * F.fold: `tpu f32 max err: 0.01838`, `cpu f32 max err: 9.97e-07`.
* Expected: error near 1e-6 (pure data movement and sums; no rounding
  needed).
* Root cause (upstream/main, code reading):
  * `csrc/ops/unfold/unfold_aten_kernels.cc:109-129`
    (`BuildUnfoldBackwardShlo`): the lowering is a `stablehlo.Convolution`
    with a 0/1 identity weight and `/*precision_config=*/{}` (line 129).
  * `csrc/ops/col2im/col2im_aten_kernels.cc:198`: same pattern.
  * Empty precision config means DEFAULT precision. On TPU, DEFAULT is a
    single bf16 pass. The global precision setting is not read here.
* Fix: C++, about 2 lines plus tests. Pass `Precision::HIGHEST` for both
  operands, with an `// EXPLICIT_PRECISION_OK=<reason>` comment
  (same pattern as `upsample_bilinear2d_aa_aten_kernels.cc:525`).
  The weight is 0/1, so HIGHEST makes it exact; these are data-movement
  ops, so the user precision setting should not apply.
* History: last changes to both files are refactors only
  (`git log upstream/main -- csrc/ops/unfold/ csrc/ops/col2im/`).
* Overlap: none. `gh` searches "unfold", "col2im", "fold",
  "precision_config": no matching issue or open PR.
  Related old PR 3809 "Improve numerical precision for convolution ..."
  (closed, did not touch these).
* Test: f32 unfold backward and F.fold vs CPU float64 with
  atol about 1e-5 in `ops_unit_test.py`. Values from `randn` make the bf16
  error show up (current error 1e-2).
* Note: the op_db sweep did not flag `nn.functional.unfold` grad, because
  its samples are small. Use `randn` inputs in the new test.

## Finding 2 - `torch.unique(x, sorted=False)` raises on TPU (confirmed)

* Impact: medium. `sorted=False` is common in user and library code
  (for speed). CPU and CUDA accept it (CUDA always sorts anyway).
* Repro: `repro_unique.py`.

```python
import torch
x = torch.tensor([3, 1, 3, 2, 1])
print("cpu:", torch.unique(x, sorted=False))
print("tpu:", torch.unique(x.to("tpu"), sorted=False).cpu())
```

* Command: `flock /root/tpu.lock timeout 60 python repro_unique.py`
* Actual: `cpu: tensor([1, 2, 3])`, then
  `RuntimeError: unique2(): sorted=False is not yet supported`.
  Also fails for f32 and bf16 (op_db sweep, 13 samples each).
* Expected: a tensor of the unique values (sorted output is allowed).
* Root cause: `csrc/ops/unique/unique_aten_kernels.cc:284-285`
  (`AtenUnique2`): `TT_CHECK_THROW(sorted, ...)`.
  The `unique(dim=...)` kernel in the same file (`AtenUniqueDim`, line 302)
  already ignores `sorted` ("does not affect SHLO") and always sorts.
* Fix: C++, small. Drop the check and always pass `sorted=true` to
  `GetUniqueCount` and `Unique2` (match CUDA and `AtenUniqueDim`).
* Overlap: none. Issue 4159 (closed) was `unique(dim=...)`. No open PR.
* Test: `torch.unique(x, sorted=False)` with `return_inverse` and
  `return_counts`, compare with CPU sorted output.

## Finding 3 - Missing ops that common models hit (confirmed)

All raise `operator '...' is not implemented for TPU`.
All are in `UNREGISTERED_OPS` in `tests/native_functions_data.py` on
upstream/main, so the gap is known to the test list, but no issue or PR
exists for them.

| Op | User call | List line | Impact |
| --- | --- | --- | --- |
| `upsample_trilinear3d.out` (+ backward) | `F.interpolate(x, mode="trilinear")` | 385-386 | Medium: 3D UNets, video, medical models |
| `adaptive_max_pool2d_backward.grad_input` | backward of `F.adaptive_max_pool2d` / `nn.AdaptiveMaxPool2d` | 175 | Medium: training any model with this layer fails; forward works |
| `kthvalue.values` | `torch.kthvalue` | 233 | Low-medium |

* Repros: `repro_trilinear.py`, `repro_amp_grad.py`, `repro_kthvalue.py`.
  Output in `repro_all.log` and the commands above.
* `adaptive_max_pool2d` repro:

```python
import torch
import torch.nn.functional as F
x = torch.randn(1, 3, 8, 8, device="tpu", requires_grad=True)
F.adaptive_max_pool2d(x, (2, 2)).sum().backward()
```

  Actual: `RuntimeError: operator 'aten::adaptive_max_pool2d_backward.grad_input'
  is not implemented for TPU`. Expected: grad with 12 ones.
* Fix: C++, new kernels. `adaptive_max_pool2d_backward` can scatter the
  grad with the forward indices (forward already exists, PR 3236).
  `upsample_trilinear3d` can follow the bilinear2d lowering.
  `kthvalue` can use sort + gather.
* Overlap: `gh` searches "trilinear", "adaptive_max_pool2d", "kthvalue":
  no issue or open PR. PR 5984 only excluded kthvalue tests.

## Dead ends (one line each)

* int64 mm/bmm/addmm/matmul/conv/pooling raise: intended (PR 5932 rejects integral dot).
* `linalg_cross`, `smooth_l1_loss`, histc bf16: known (issue 6111 fix on a branch, PRs 6747/6748).
* `pad(mode="replicate")` with a negative pad larger than the size raises; normal negative pads work. Edge case, skipped.
* `binary_cross_entropy` 5e-4 diff near input 1: TPU uses `log1p(-x)`, CPU `log(1-x)`; rounding only.
* argsort bf16 / f32 index diffs: ties only; gathered values are sorted; `stable=True` matches CPU.
* bf16 diffs in matmul, cdist, conv_transpose2d, grid_sample, instance_norm: bf16 rounding size.
* `norm(p="nuc")` 1.5e-4 relative diff (SVD precision), low value.
* dropout value diff: different RNG, expected.
* gather backward with an empty 2-D index on a 1-D input raises: exotic op_db sample, skipped.
* `nonzero` is slow per new shape (known issue 5085); it made two sweep chunks hit the timeout.
* op_db needs `pip install expecttest` (installed). Build op lists with `TORCH_DEVICE_BACKEND_AUTOLOAD=0` to avoid opening the TPU.
