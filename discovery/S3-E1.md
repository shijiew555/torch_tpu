## Finding 1 - `torch.utils.checkpoint` does not restore the TPU RNG state, so dropout gradients are wrong (CONFIRMED)

* Impact: HIGH. Silent wrong gradients.
  Every model that uses eager activation checkpointing (HF
  `gradient_checkpointing_enable()`, torchtitan AC) and dropout gets wrong
  gradients on TPU.
  There is no error and no warning.
* Repro: `$COORD/scratch/S3-E1/ckpt_dropout.py`

```python
import sys
import torch
import torch_tpu  # noqa: F401
from torch import nn
import torch.utils.checkpoint as cp

print("hasattr(torch.tpu, '_initialized'):", hasattr(torch.tpu, "_initialized"))
if len(sys.argv) > 1:  # Simulated fix.
  torch.tpu._initialized = True

for dev in ("cpu", "tpu"):
  for reentrant in (True, False):
    torch.manual_seed(0)
    lin = nn.Linear(8, 8).to(dev)
    drop = nn.Dropout(0.5)
    f = lambda x: drop(lin(x))
    x = torch.randn(4, 8, device=dev, requires_grad=True)
    torch.manual_seed(1)
    cp.checkpoint(f, x, use_reentrant=reentrant).sum().backward()
    g_ckpt = x.grad.clone()
    x.grad = None
    torch.manual_seed(1)
    f(x).sum().backward()
    print(f"{dev} use_reentrant={reentrant}: grad diff vs no checkpoint =",
          (g_ckpt - x.grad).abs().max().item())
```

* Command: `python ckpt_dropout.py` (bug), `python ckpt_dropout.py fix`
  (simulated fix).
* Actual (no argument):

```
hasattr(torch.tpu, '_initialized'): False
cpu use_reentrant=True: grad diff vs no checkpoint = 0.0
cpu use_reentrant=False: grad diff vs no checkpoint = 0.0
tpu use_reentrant=True: grad diff vs no checkpoint = 1.5137939453125
tpu use_reentrant=False: grad diff vs no checkpoint = 1.5137939453125
```

* With `fix`: all four lines give `0.0`.
* Expected: `0.0` on TPU, as on CPU.
* Model-level check (`followup2.py e2e`): two
  `nn.TransformerEncoderLayer(dropout=0.1)` layers, `checkpoint(...,
  use_reentrant=False)` vs no checkpoint, same seed. Relative grad
  difference of `linear1.weight`: CPU `0`, TPU `0.705`.
* `torch.compile(backend="tpu")` with checkpoint is correct (grad diff
  0.0). The compiled path uses graphsafe RNG (PR 5067). Only eager is
  broken.
* Root cause: `torch/utils/checkpoint.py` saves device RNG states only if
  `getattr(device_module, "_initialized", False)` is true
  (`CheckpointFunction.forward` and `_checkpoint_without_reentrant_generator`).
  CUDA, XPU and HPU define `_initialized`. `torch.tpu` does not
  (`src/torch_tpu/_internal/public_api.py` `_PUBLIC_MODULES["torch.tpu"]`
  and `_TPU_DEVICE_CLASS` in
  `src/torch_tpu/_internal/device/_device_module.py` have no
  `_initialized`). So checkpoint never saves the TPU RNG state, and the
  recompute draws a new dropout mask.
  `get_rng_state` / `set_rng_state` and `torch.random.fork_rng(device_type=
  "tpu")` work; they are just never called.
* Status on main: same (no `_initialized` in `src/torch_tpu` on
  `upstream/main`; `git log afd6943a..upstream/main -S_initialized -- src`
  is empty).
* Fix: Python-only. Add a `_initialized` attribute (a class property on
  `_DeviceModuleMeta` that returns `is_initialized()`, or a `Property`
  export) so `getattr(torch.tpu, "_initialized")` is true after TPU init.
  About 10 lines plus a test. Check how `private_fallback` resolves class
  properties, and that the `tt_apis.yaml` API test does not need a change
  (it is a private name).
* Test: eager `checkpoint` with dropout, both `use_reentrant` values,
  compare grads with a non-checkpointed run (as in the repro). Add to the
  activation checkpointing tests (the ported upstream tests in
  `tests/compile/upstream_activation_checkpointing_test.py` cover only
  compiled AC).
* Overlap: no issue or PR found (`gh` searches: "checkpoint dropout",
  "checkpoint rng", "gradient checkpointing", "_initialized",
  "preserve_rng_state"). Related but different: PR 5067 (compiled AC RNG),
  PR 6550 (excluded compiled AC tests).

## Finding 2 - `torch.amp.GradScaler` does not work on TPU (CONFIRMED)

* Impact: HIGH. fp16 mixed precision training cannot use loss scaling.
  `torch.autocast("tpu")` defaults to float16 (session 1 finding), so
  GradScaler is the normal partner.
* Repro: `$COORD/scratch/S3-E1/gradscaler.py`

```python
import torch
import torch_tpu  # noqa: F401
from torch import nn

m = nn.Linear(8, 2).to("tpu")
opt = torch.optim.SGD(m.parameters(), lr=0.1)
scaler = torch.amp.GradScaler("tpu")
with torch.autocast("tpu", dtype=torch.float16):
  loss = m(torch.ones(4, 8, device="tpu")).sum()
scaler.scale(loss).backward()
scaler.step(opt)  # Raises here.
scaler.update()
print("scale", scaler.get_scale())
```

* Actual:
  `RuntimeError: operator 'aten::_amp_foreach_non_finite_check_and_unscale_' is not implemented for TPU. Please file a feature request`
  (from `scaler.step` / `scaler.unscale_`).
  `torch._amp_update_scale_` on TPU gives the same error for
  `aten::_amp_update_scale_` (`followup2.py amp`).
* `torch.amp.GradScaler()` with no device picks `tpu` and is enabled, so
  it also fails at `step`.
* Expected: as on CUDA. `step` is skipped when a grad is inf/nan, and the
  scale is halved.
* Status on main: both ops are in `UNREGISTERED_OPS`
  (`tests/native_functions_data.py:30-31`).
* Overlap: PR 2464 "Implement `_amp_foreach_non_finite_check_and_unscale_`
  and `_amp_update_scale_` natively in TorchTPU" (internal CL 952893244)
  was CLOSED unmerged on 2026-08-17 with no comment. Ask maintainers why
  before work starts. No issue found.
* Fix: C++. Two kernels (any-nonfinite over a tensor list plus in-place
  multiply; scale/growth-tracker update). Precedent:
  `csrc/ops/foreach_aten_kernels.cc` and the fused optimizer kernels
  (`_fused_adagrad_`, PR 2226). About 100-150 lines plus tests.
* Test: GradScaler step with finite grads matches CPU; step with an inf
  grad leaves params unchanged and halves the scale; growth after
  `growth_interval` steps.

## Finding 3 - `torch.distributions` samplers are missing: Gamma, Beta, Dirichlet, Chi2, StudentT, Poisson, Binomial (CONFIRMED)

* Impact: MEDIUM. RL (PPO with Beta policies), VAEs, Bayesian code.
  Normal, Categorical, Bernoulli, MVN, Uniform, Exponential, Laplace,
  Multinomial, OneHotCategorical, RelaxedBernoulli, gumbel_softmax and
  `kl_divergence` work, and `log_prob` / `entropy` match CPU.
* Repro: `$COORD/scratch/S3-E1/sample_ops.py`
* Actual:

```
Gamma FAIL: operator 'aten::_standard_gamma' is not implemented for TPU. Please file a feature request
Beta FAIL: operator 'aten::_sample_dirichlet' is not implemented for TPU. Please file a feature request
Dirichlet FAIL: operator 'aten::_sample_dirichlet' is not implemented for TPU. Please file a feature request
Poisson FAIL: operator 'aten::poisson' is not implemented for TPU. Please file a feature request
Binomial FAIL: operator 'aten::binomial' is not implemented for TPU. Please file a feature request
```

* StudentT and Chi2 fail on `_standard_gamma` too.
* Status on main: `_standard_gamma`, `_standard_gamma_grad`,
  `_sample_dirichlet`, `_dirichlet_grad`, `poisson`, `binomial` are all in
  `UNREGISTERED_OPS`.
* Fix: C++. `_standard_gamma` needs a rejection sampler
  (Marsaglia-Tsang) in StableHLO with the TPU RNG; `_sample_dirichlet` =
  gamma then normalize. Medium size (gamma + grad is more than 50 lines).
  The error is clear, so this is a feature gap, not a crash.
* Overlap: no issue or PR found ("standard_gamma", "dirichlet",
  "poisson", "binomial").

## Finding 4 - `parametrizations.orthogonal` default map fails: `linalg_matrix_exp` and `linalg_householder_product` missing (CONFIRMED)

* Impact: LOW. `orthogonal(layer)` (default `matrix_exp` map for square
  weights) and `orthogonal_map="householder"` fail. `"cayley"` works.
  `weight_norm` and `spectral_norm` match CPU after 3 SGD steps.
* Repro: `components.py parametrizations`.
* Actual: `operator 'aten::linalg_matrix_exp' is not implemented for TPU`,
  `operator 'aten::linalg_householder_product' is not implemented for TPU`.
* Status on main: both in `UNREGISTERED_OPS`; `matrix_exp` error is
  pinned in `tests/tpu_errors_test.py:5046`, so it is a known gap.
* Fix: C++, medium (Pade + scaling and squaring). Low priority.
