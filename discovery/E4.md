## Finding 1 - `torch.Stream("tpu")` without an index fails (confirmed)

* Device-agnostic code such as
  `torch.Stream(device=torch.accelerator.current_accelerator())` or
  `torch.Stream("tpu")` raises. With an explicit `tpu:0` it works.
  On CUDA, a device with no index means "current device".
* Repro `/root/torch_tpu/.claude/tmp/E4/repro_stream.py`:

```python
import torch
import torch_tpu  # noqa: F401

print(torch.Stream("tpu:0"))  # works
print(torch.Stream(device=torch.accelerator.current_accelerator()))  # fails
```

* Command:
  `flock /root/tpu.lock timeout 240 bash .claude/tmp/E4/run_confirm.sh`
  (sets `PYTHONPATH` to the upstream/main overlay). Log `confirm_main.log`.
* Actual:

```
torch.Stream device_type=tpu, device_index=0, stream_id=1
RuntimeError: expected device index to be >= 0, got -1
```

* Expected: `torch.Stream device_type=tpu, device_index=0, stream_id=...`
  for both lines (CUDA: `CUDAGuardImpl::getNewStream` calls
  `getStreamFromPool(priority, d.index())`, and index -1 means current
  device).
* Root cause: `csrc/eager/tpu_hooks.cc:222-226` (upstream/main)
  `TpuDeviceGuardImpl::getNewStream` passes `d` with index -1 to
  `ValidateDevice` -> `ValidateDeviceIndex` (`tpu_hooks.cc:81-87`). The
  comment at line 82 says this "should not be hit", so the case was missed.
  `getStream` (line 215) has the same pattern.
* Fix (C++, about 5 lines): in `getNewStream` (and `getStream`), replace a
  negative index with `GetCurrentDeviceIndex()` before validation. Tests:
  `torch.Stream("tpu")` and `torch.Stream(device=torch.device("tpu"))`
  return a stream on `tpu:0`.
* Related: PR #6737 (bot, open) refactors this file
  (`TpuDeviceGuardImpl` -> `TpuDeviceGuard`) but does not change index
  handling. Expect a merge conflict; rebase after it lands. Not part of
  #6216 (feature request for D2H/H2D stream control).
  Searches: "torch.Stream", "Stream device index", "getNewStream",
  "device index -1" - no match.

## Finding 2 - every `x.to("tpu", non_blocking=True)` of unpinned memory emits two DeprecationWarnings (confirmed)

* A normal training loop `batch.to(device, non_blocking=True)` with a
  DataLoader without `pin_memory=True` prints two torch DeprecationWarnings
  per call site. `copy_(..., non_blocking=True)` does the same. With
  `warnings.simplefilter("error")` or pytest `-W error`, the call raises.
  Results are correct.
* Repro `/root/torch_tpu/.claude/tmp/E4/repro_pin_warn.py`:

```python
import torch
import torch_tpu  # noqa: F401

batch = torch.ones(4)  # not pinned, as from a DataLoader with pin_memory=False
y = batch.to("tpu", non_blocking=True)
print(y.cpu())
```

* Actual (upstream/main overlay, `confirm_main.log`):

```
repro_pin_warn.py:5: DeprecationWarning: The argument 'device' of Tensor.pin_memory() is deprecated. Please do not pass this argument. (Triggered internally at .../aten/src/ATen/native/Memory.cpp:46.)
repro_pin_warn.py:5: DeprecationWarning: The argument 'device' of Tensor.is_pinned() is deprecated. Please do not pass this argument. (Triggered internally at .../aten/src/ATen/native/Memory.cpp:31.)
tensor([1., 1., 1., 1.])
```

  `repro_pin_warn_default.py` (warnings as errors) raises
  `DeprecationWarning` from the `.to(...)` call.
* Expected: no warning (CUDA does not warn here).
* Root cause: `csrc/ops/copy_from/cpu_to_tpu.cc:125` (upstream/main):
  `effective_src = effective_src.pin_memory(dest.device());`.
  Torch 2.14 deprecated the `device` argument.
* Fix (C++, 1 line): `effective_src.pin_memory()`. With no argument, torch
  uses the current accelerator (TPU, PrivateUse1), so behavior is the same.
  Check that the result still passes `IsTpuPinnedPtr`. Test: run a
  non-blocking H2D copy of an unpinned tensor under
  `warnings.simplefilter("error")`.
* Searches: "pin_memory", "pin_memory deprecated",
  "DeprecationWarning pin_memory", "non_blocking warning" - no match.

## Observations (not bugs, or design)

* `torch.tpu.synchronize/is_available/device_count/current_device/
  set_device/current_stream/get_rng_state/initial_seed/device(...)` raise
  "internal to TorchTPU and can only be called by the PyTorch framework".
  This is the API policy (points to `torch.accelerator.*`). Code that calls
  `torch.get_device_module("tpu").synchronize()` will fail. Design choice;
  related to #4413.
* `safetensors.load_file(..., device="tpu")` fails in safetensors (Rust):
  `SafetensorError: device tpu is invalid`. Third-party; load to CPU then
  `.to("tpu")` works.

## Dead ends (all pass, no bug)

* `.to("tpu")`, `.to(dtype)`, bf16/fp16/f64/int64>2^32/uint8/bool/complex
  round trips, `.cpu()` of transpose/slice/step views, `tolist`, `item`,
  `torch.tensor(..., device=)`, `from_numpy` (also non-contiguous),
  `as_tensor`, channels_last, `copy_` across devices/dtypes/non-contiguous.
* `non_blocking` H2D/D2H with sync or event, source mutated after the call,
  pinned source.
* DataLoader `num_workers=0/2`, `pin_memory=True/False`.
* `torch.save/load` (default `weights_only=True`), `map_location` str/dict/
  device/cpu/tpu, `mmap=True`, shared-storage views, full module pickle,
  `load_state_dict(assign=True)`, meta init + `to_empty`, `deepcopy` of
  tensors and modules, `with torch.device("tpu")`, `set_default_device`.
* RNG: `manual_seed` repro (eager and compiled dropout/randn_like),
  `torch.Generator("tpu")` seed/state, explicit generator does not advance
  the global one, `fork_rng(device_type="tpu")`, randperm, multinomial.
* `torch.accelerator.*` memory/sync/stream APIs, `torch.Event` timing,
  `torch.tpu.Stream/Event`, `get_device_module`.
* `deepcopy` drops `.grad` - same on CPU.
* safetensors "RuntimeError with empty message" - it was the multi-line
  shared-tensor error for a view; expected.
* `tpu:1` on one chip gives a clear out-of-bounds error.
