## Finding 1 - max_pool1d/2d/3d and avg_pool1d abort the process when the output size is < 1 (confirmed)

* Common user mistake: a pool window larger than a small feature map
  (`nn.MaxPool2d(3)` on a 2x2 map). Also any zero-size spatial dim.
* Repro: `scratch/S3-E3/repro_pool_small.py`, `repro_maxpool_empty.py`.
* Command:
  `flock /root/tpu.lock timeout 300 .venv/bin/python repro_pool_small.py max2d`
  (also `max1d`, `max2d_grad`, `max2d_module`, `max3d`, `avg1d`,
  `max2d_empty_spatial`).
* Actual (exit 134, SIGABRT, on the execution thread):

```
cpu RuntimeError Given input size: (1x2x2). Calculated output size: (1x0x0). Output size is too small
F0000 device_buffer.cc:550] Check failed: at_shape.dimensions()[d] == buffer_dims[d] (1 vs. 0)
Expected the size of dimension 2 of the PjRtBuffer of shape [1, 1, 0, 0] to match the size of
the same dimension of this DeviceBufferList of shape [1, 1, 1, 1], got 0.
  torch_tpu::DeviceBufferList::CheckMaterialization() <- ExecutionTask::RunInternal()
```

* Expected: the CPU `RuntimeError` (GPU raises the same, the check is in
  shared ATen code).
* Works: `max_pool2d(..., return_indices=True)`, `avg_pool2d`,
  `avg_pool3d`, `adaptive_*` raise the right error.
* Root cause (main):
  * `csrc/ops/pooling/pooling.cc:374` `GetPoolingOutputSize` clamps each
    output dim with `std::max<int64_t>(out, 1)` and does no validation.
    The XLA reduce_window result has size 0, the declared buffer has
    size 1, so the materialization check aborts.
  * `src/torch_tpu/_internal/pooling/patch.py:383-432`
    `patched_max_pool1d/2d/3d` call `torch.ops.tpu._max_pool*d` directly,
    so the ATen input checks (`pool2d_shape_check`, non-zero spatial
    dims) never run.
  * `avg_pool_aten_kernels.cc:641` `AtenAvgPool1d` uses the same helper.
* Fix: C++, about 30-40 lines plus tests. In `GetPoolingOutputSize`,
  return `kInvalidArgument` when an output dim is < 1 (message like
  ATen "Output size is too small") and when a spatial input dim is 0.
  Also check kernel > 0, stride > 0, dilation > 0, padding <= kernel/2.
  Check why the clamp was added (commit `5fc41fd4d`, "Refactor pooling
  output shape calculation"); ceil_mode may need the clamp kept only for
  valid inputs.
* Test: `errors_test.py` cases for `F.max_pool1d/2d/3d` and
  `F.avg_pool1d` with kernel > input and with a zero spatial dim, eval
  and `requires_grad=True`. op_db `error_inputs` of max_pool1d/2d/3d also
  cover it.
* Overlap: searched "max_pool", "max_pool output size", "pooling abort",
  "Check failed device_buffer", "LLVM ERROR": no match.
* Impact: high. Kills the Python process (Jupyter kernel dies) on a
  common shape mistake; no Python traceback.

## Finding 2 - SDPA with mismatched q/k/v shapes aborts the process or gives MLIR errors (confirmed)

* Repro: `scratch/S3-E3/repro_sdpa_shapes.py <case>`,
  `repro_sdpa_headdim.py`.
* Command: `flock /root/tpu.lock timeout 300 .venv/bin/python repro_sdpa_shapes.py qk_headdim`
* Actual per case (q, k, v shapes):

| case | shapes | CPU | TPU |
| --- | --- | --- | --- |
| qk_headdim | q[...,8] k[...,6] | RuntimeError (bmm size) | abort: `LLVM ERROR: Failed to infer dot op type` |
| kv_seqlen | k seq 5, v seq 6 | ok (CPU bug) | abort: same LLVM ERROR |
| kv_heads_more | q 2 heads, kv 4 heads, enable_gqa | RuntimeError "Number of heads in key and value must divide..." | abort: same LLVM ERROR |
| batch | q batch 2, kv batch 3 | RuntimeError size mismatch | RuntimeError `failed to inline functions in MLIR module` |
| kv_heads_mismatch | k 2 heads, v 1 head | ok | RuntimeError `failed to inline functions in MLIR module` |
| mask_bad | mask [3,5] for [1,2,4,4] | RuntimeError size mismatch | RuntimeError with MLIR text `Cannot broadcast input: 'tensor<3x5xf32>'` |

* Expected: a clean `RuntimeError` naming the bad dims. GPU raises in
  `sdp_utils` checks or in the math path.
* Root cause (main): `csrc/ops/scaled_dot_product_attention/`
  `scaled_dot_product_attention_shlo.cc:187` `ValidateAttentionInputs`
  checks only rank and static dims. It does not check that q/k head dims
  match, k/v seq lens match, batch dims match, kv heads <= q heads, or the
  mask broadcast. It also runs inside the MLIR builder (lazy, on the
  compile path), and `stablehlo::DotGeneral` calls
  `llvm::report_fatal_error`. Eager entry
  `AtenScaledDotProductFusedAttentionOverrideable`
  (`scaled_dot_product_attention_aten_kernels.cc`) has no shape check.
* Fix: C++, about 40 lines plus tests. Validate at::Tensor shapes in the
  eager kernel (and backward) before `DispatchOp`: batch dims equal,
  q/k head dim equal, k/v seq len equal, k/v head count equal and divides
  q heads, mask broadcastable to [..., Lq, Lk].
* Test: `errors_test.py` cases per mismatch above, also under
  `torch.compile` (meta checks may already catch some there).
* Overlap: searched "LLVM ERROR", "Failed to infer dot op type", "sdpa
  head dim mismatch", "scaled_dot_product_attention validate", "attention
  abort": no match (only closed #5952 avg_pool2d compile abort, other
  op).
* Impact: high. Attention code is in every transformer; a shape bug while
  writing a model kills the process.

## Finding 3 - layer_norm with a wrong normalized_shape returns zeros or an MLIR error (confirmed)

* Repro: `scratch/S3-E3/repro_norm_shape.py`.
* Command: `flock /root/tpu.lock timeout 300 .venv/bin/python repro_norm_shape.py`
* Actual:

```
layer_norm_shape  F.layer_norm(randn(2,3), (4,))
  cpu: RuntimeError: Given normalized_shape=[4], expected input with shape [*, 4], but got input of size[2, 3]
  tpu: ok shape=(2, 3) sum=0.0000          <- silent wrong result (all zeros)
layer_norm_shape_same_numel  F.layer_norm(randn(2,6), (3,2))
  tpu: ok shape=(2, 6) sum=0.0000          <- silent wrong result
layer_norm_module  nn.LayerNorm(768) on randn(2,512)
  tpu: RuntimeError: layer_norm(): failed to broadcast tensor: <unknown>:0: error: Cannot broadcast
       input: 'tensor<768xf32>' to target shape tensor<2x512>
layer_norm_weight  weight shape [4], normalized_shape (3,)
  tpu: RuntimeError: layer_norm(): failed to broadcast tensor: ... 'tensor<4xf32>' to target shape tensor<2x3>
```

  op_db `native_layer_norm` error inputs #1, #2, #3 show the same.
  The failed cases also log `[SetAsError] Failed to set materialization
  error: FAILED_PRECONDITION` twice (noise).
* Expected: the CPU messages. `rms_norm` and `group_norm` on TPU already
  give good messages (precedent: `rms_norm(): expected input trailing
  dimensions to match normalized_shape [4], got input of shape [2, 3]`).
* Root cause (main): `csrc/ops/layer_norm/layer_norm_aten_kernels.cc:53`
  `ValidateInputs` checks dtype, non-empty, and rank only. No check that
  `input.sizes()` ends with `normalized_shape`, and no weight/bias shape
  check. Unchanged since `afd6943a`.
* Fix: C++, about 20 lines plus tests, copy the rms_norm checks. Use in
  `AtenNativeLayerNorm` and `AtenLayerNormBackward`.
* Test: `errors_test.py` for the 4 cases above; op_db error inputs.
* Overlap: searched "layer_norm normalized_shape", "layer_norm shape":
  only #5678/PR 5691 (bf16 weight dtype, other topic).
* Impact: high for the silent case (wrong normalized_shape gives zeros
  and training goes on), medium for the MLIR message.

## Finding 4 - `uniform_` and `exponential_` accept invalid parameters (confirmed)

* Repro: `scratch/S3-E3/repro_rng_params.py`.
* Actual:

```
uniform_(3, -1)    cpu: RuntimeError: uniform_ expects to return a [from, to) range, but found from=3 > to=-1
                   tpu: ok [-0.43, 0.21, 2.56, 1.06, -0.51]
uniform_(0, inf)   cpu: RuntimeError: to is out of bounds for float      tpu: ok [inf, ...]
exponential_(0)    cpu: RuntimeError: exponential_ expects lambda > 0.0  tpu: ok [inf, ...]
exponential_(-1)   cpu: RuntimeError                                      tpu: ok [negative values]
nn.init.uniform_(t, a=1, b=0)  cpu: RuntimeError  tpu: ok
```

* Expected: CPU errors (shared ATen checks, so GPU raises too).
  `normal_`, `bernoulli_`, `random_` on TPU already check (precedent:
  `ValidateNormalStdPreconditions`, `normal_aten_kernels.cc:271`).
* Root cause (main): `csrc/ops/uniform/uniform_aten_kernels.cc:67`
  `AtenUniform_` (no from/to check; `ValidateUniformPreconditions` at
  line 56 checks dtype only) and
  `csrc/ops/exponential/exponential_aten_kernels.cc:124`
  `AtenExponential_` (no lambda check).
* Fix: C++, about 15 lines plus tests. uniform: `from <= to`, both
  finite and in dtype range (ATen `check_uniform_bounds`). exponential:
  `lambd > 0`.
* Test: `errors_test.py`; op_db error inputs of `uniform` and
  `exponential` already cover it.
* Overlap: searched "exponential lambda", "exponential_", "uniform_ from
  to": only #5807 / PR 5899 (exact zeros, other topic).
* Impact: medium. Silent garbage for bad init ranges; rare but easy fix.

## Finding 5 - `TORCH_TPU_ENABLE_DEBUG_CHECKS=1` checks indices only for `take` and `histc`/`bincount` (confirmed)

* Out-of-range indices are silent on TPU by design (no device asserts),
  and `docs/api_reference.md:384-401` says to use
  `TORCH_TPU_ENABLE_DEBUG_CHECKS=1` to catch them.
* With the flag, these still return garbage (CPU raises, GPU device
  asserts): `embedding` (index 10 or -1), `index_select`, `gather`,
  `x[idx]`, `x[idx] = v`, `scatter`, `scatter_add`, `index_add`,
  `index_put`, `F.one_hot`, `F.cross_entropy` / `F.nll_loss` with target
  out of range (returns a finite loss), `binary_cross_entropy` with
  target > 1, `multinomial` with negative probabilities.
* Repro: `TORCH_TPU_ENABLE_DEBUG_CHECKS=1 flock /root/tpu.lock timeout
  600 .venv/bin/python scratch/S3-E3/mistakes.py embedding_oob
  ce_target_oob index_select_oob gather_oob take_oob`.
  Output (TPU): `embedding_oob ok tensor([[1., 1.], [1., 1.]])`,
  `ce_target_oob ok tensor(2.3664)`; only `take_oob` raises
  `IndexError: take(): expected indices to be in range [-5, 4], got 9`.
* Root cause (main): `GetEnableDebugChecks()` is used only in
  `csrc/ops/take/take_aten_kernels.cc:123` and
  `csrc/ops/histc/histc_aten_kernels.cc:559`.
* Fix: C++, about 15-25 lines per op, reusing the
  `ValidateIndicesInRange` pattern of take (debug check plus a
  `TT_WARN_ONCE` otherwise). Start with embedding, nll_loss target,
  index_select, gather. Could be a series of small PRs.
* Overlap: no issue or PR found ("out of bounds indices silently",
  "cross_entropy target", "index out of range").
* Impact: medium. Wrong vocab size or label ids is a common bug; the
  documented debug flag does not find it. Maintainers may see this as a
  feature request; ask in an issue first.

## Other sweep results (lower value)

* `out=` overlap checks missing (CPU raises "unsupported operation ...
  refer to a single memory location", TPU writes): `cat` (#6-8),
  `gather` (#6-7), `take` (#1-2), `aminmax` min/max out overlap (#4).
  `masked_select.out` is PR 6838 (skip). Low impact.
* `max_pool1d` on a 2-D input with 0 channels `[0, 10]`: CPU raises,
  TPU returns empty. Part of Finding 1.
* `narrow_copy` dim 3 on 3-D: TPU `IndexError` (clean), CPU internal
  `RuntimeError`. TPU is better.
* `linalg.eig` fp16: TPU "not implemented for TPU" vs CPU
  NotImplementedError. Expected.
* `adaptive_max_pool2d(output_size=())`: "internal error" text, same on
  CPU. Not TPU.
* Integer `//` and `%` by zero: TPU returns -1 / 1, CPU raises
  ZeroDivisionError. GPU also returns garbage. Not a bug.
* `roll` #0, #2, #3 no error: fixed on main (`6c3bd5c8e`).

## Tried, works (TPU error is clean)

* Mixed CPU/TPU tensors in add, matmul, where, out= (clear "expected
  tensor to be on tpu, got cpu").
* cat/stack dtype and shape, view on non-contiguous, view/reshape numel,
  out= dtype, mm/bmm/linear shape and dtype, conv channel/rank/kernel too
  big, batch_norm channels, softmax/sum/transpose/permute dim, expand,
  broadcast, in-place broadcast/dtype, leaf in-place, non-scalar
  backward, item on multi-element, `.numpy()`, split/chunk/narrow/select,
  randint/normal/bernoulli/random_ params, empty/zeros/full negative
  sizes, arange/linspace bad args, max/argmax empty, mean/std on int,
  repeat_interleave negative, masked_fill mask dtype/shape, float
  indices, cross_entropy target shape and dtype, interpolate, pad,
  avg_pool padding, clamp min > max, cholesky/inv/solve singular and
  non-square, rms_norm, group_norm.
* `bincount` negative input: raises with debug checks.

## Dead ends

* gather/scatter/index OOB without the debug flag: by design (docs). See
  Finding 5 for the actual gap.
* multinomial with negative/zero probabilities: data-dependent, same
  class as OOB indices.
* `topk`, `eye`, `masked_select.out`, `linalg.solve_ex`, `roll`, `flip`,
  `softmax` dim: open PRs or fixed on main.
* `cauchy_`, `log_normal_`, `geometric_`: not registered for TPU (clear
  "not implemented" error).

## Method notes

* Sweep: `worker.py` runs each op's `error_inputs` on CPU and on TPU and
  pairs them by error regex (some generators skip samples per device;
  unpaired CPU samples are moved to TPU). `driver.py` runs chunks of 30
  ops under the TPU lock and restarts after an abort. `analyze.py`
  classifies. Results: `sweep_flagged.txt`, full `sweep.jsonl.gz`.
* User mistakes: `mistakes.py` (about 120 cases), summary in
  `mistakes_summary.txt`.
